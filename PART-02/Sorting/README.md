## 06. 정렬

### 정렬이란?

정렬이란 데이터를 특정한 기준에 따라서 순서대로 나열하는 것

### 선택 정렬 (Selection Sort)

선택 정렬이란, 가장 작은 값을 선택해서 순서대로 정렬하는 알고리즘이다.

### 선택 정렬 과정

1. 전체 데이터 중에서 가장 작은 값을 찾는다.
2. 찾은 값을 데이터의 맨 앞으로 보낸다.
3. 이제 맨 앞자리는 정렬이 끝났다고 생각하고, 나머지 데이터 중에서 다시 가장 작은 값을 찾는다.
4. 찾은 값을 두 번째 자리로 보낸다.
5. 이 과정을 모든 데이터가 정렬될 때까지 반복한다.

### 선택 정렬 평가

알고리즘의 동작 원리를 이해하기 쉽다는 장점이 있지만, 시간 복잡도는 $O(n^2)$ 으로 비효율적이기 때문에 실제 서비스에서는 거의 사용되지 않는다.

### 삽입 정렬 (Insertion Sort)

삽입 정렬이란, 데이터를 하나씩 확인하며 이미 정렬된 부분의 올바른 위치에 삽입하는 방식의 알고리즘이다.

### 삽입 정렬 과정

1. 두 번째 데이터부터 시작한다. (첫 번째 데이터는 그 자체로 '정렬된' 상태로 본다.)
2. 선택한 데이터가 자신의 앞쪽(이미 정렬된 부분)에 있는 데이터들보다 작다면, 자리를 바꾼다.
3. 계속해서 앞쪽의 올바른 위치를 찾아 들어갈 때까지 이 과정을 반복한다.
4. 이 과정을 마지막 데이터까지 진행하면 전체 정렬이 끝난다.

### 삽입 정렬 평가

삽입 정렬 역시, 알고리즘이 직관적이라는 장점이 있다. 또한, 데이터가 이미 정렬되어 있거나 거의 정렬된 상태라면, 시간 복잡도가 $O(n)$에 가까워져 매우 효율적인 모습을 보여준다. 하지만, 평균 $O(n^2)$이라는 비효율적이라는 시간 복잡도로 인해, 삽입 정렬 역시 단독으로는 잘 쓰이지 않지만 다른 고급 정렬 알고리즘의 일부로 사용되어 빛을 발하는 경우도 있다.

### 퀵 정렬 (Quick Sort)

퀵 정렬이란, 전체 데이터를 특정 기준을 중심으로 두 개의 그룹으로 나눈 뒤, 각 그룹에 대해 똑같은 작업을 반복하는 방식의 알고리즘이다.

### 퀵 정렬 과정

1. 데이터 중 아무거나 하나를 기준(Pivot)으로 잡는다. (ex. 첫 번째 데이터)
2. 왼쪽에서부터 Pivot보다 큰 데이터를 찾고, 오른쪽에서부터 Pivot보다 작은 데이터를 찾는다.
3. 그다음 큰 데이터와 작은 데이터의 위치를 서로 교환한다.
4. 2, 3번 과정을 반복하다가 왼쪽에서부터 찾는 값과 오른쪽에서부터 찾는 값의 위치가 서로 엇갈린 순간, 작은 데이터와 Pivot의 위치를 서로 변경한다.
5. Pivot을 기준으로 왼쪽에는 Pivot보다 작은 값, 오른쪽에는 Pivot보다 큰 값이 위치해있다. 이러한 상태에서 왼쪽 리스트와 오른쪽 리스트를 개별적으로 다시 1~5번 과정을 분할이 불가능할 때(데이터 개수가 1개인 경우)까지 수행한다.

### 퀵 정렬 평가

평균적으로 시간 복잡도가 $O(NlogN)$으로, 매우 빠른 속도를 보여준다. 이에 따라 수많은 프로그래밍 언어와 시스템에서 표준 정렬 라이브러리의 일부 또는 기반 기술로 채택되었다. 한 가지 기억해둘 점은, 최악의 경우 시간 복잡도가 $O(n^2)$이라는 것이다. 리스트의 가장 왼쪽 데이터를 Pivot으로 삼을 때, '이미 데이터가 정렬되어 있는 경우'에는 매우 느리게 동작한다.

### 계수 정렬 (Count Sort)

계수 정렬은 특정한 조건이 부합할 때만 사용할 수 있지만 매우 빠른 정렬 알고리즘이다.

### 계수 정렬 과정

1. 리스트의 인덱스가 모든 범위를 포함할 수 있도록 리스트를 선언한다.(예를 들어, 데이터가 모두 양수이며 가장 큰 데이터가 '9'이고 가장 작은 데이터가 '0' 라면, 크기가 10인 리스트를 선언한다. 음수 값이 포함되었거나, 0부터 시작하지 않고 만약 10~20의 숫자 범위라면, 오프셋 조정이 필요하다.) 처음에는 리스트의 모든 데이터가 0이 되도록 초기화한다.
2. 그다음 데이터를 하나씩 확인하며 데이터의 값과 동일한 인덱스의 데이터를 1씩 증가시키면 계수 정렬이 완료된다. 정렬 결과를 확인하고 싶다면, 리스트의 첫 번째 데이터부터 하나씩 그 값만큼 인덱스를 출력하면 된다.

### 계수 정렬 평가

시간 복잡도는 $O(n + k)$ (k는 데이터 중 최대값의 크기)로, 매우 효율적인 알고리즘이다. 하지만, $k$ 값이 매우 커지면 공간 및 시간 복잡도 측면에서 비효율적이므로, 데이터 범위가 제한적인 경우에만 최적의 성능을 발휘한다.
